# AI製造ワークフロー

## 目的

AIの製造スピードを活かしつつ、人間が全量CDIしなくても品質を確認できる運用にする。

## 標準フロー

```text
1. 人間が仕様と変更禁止範囲を書く
2. AIに作業前ゲートだけ出させる
3. 人間が作業前ゲートだけ確認する
4. AIに修正差分だけ出させる
5. AIに受入条件チェック表を出させる
6. AIに追加テストケースを出させる
7. 人間は差分・DB影響・CSV項目数・例外処理だけ確認する
8. 人間が実機テストする
9. 合格したものだけ取り込む
```

## AIに任せること

- 実装案作成
- 最小差分修正
- テストケース案作成
- 影響範囲案作成
- コードレビュー観点抽出
- 報告書ドラフト作成

## 人間が握ること

- 仕様
- 受入条件
- 変更禁止範囲
- DB影響判断
- 本番適用判断
- 最終品質保証

## AIに丸投げしないこと

- 本番障害の原因断定
- DB変更の最終判断
- トランザクション設計の最終判断
- 顧客影響判断
- リリース可否判断
- 完了判定

## 違反時の対応

AIが品質ゲートに違反した場合、すぐに再修正させない。  
先に自己監査を実施させる。

```text
品質ゲート違反です。
修正版コードはまだ出力しないでください。
以下の観点で自己判定してください。

1. 変更許可範囲外を変更していないか
2. 仕様にない処理を追加していないか
3. 変更禁止事項に触れていないか
4. 未確認事項を確認済みのように書いていないか
5. 出力形式を守っているか
```

## 最終原則

AIがルールを守ることを期待しない。  
ルールを守っていることを、出力構造・差分・受入条件・テストで確認できない成果物は採用しない。
