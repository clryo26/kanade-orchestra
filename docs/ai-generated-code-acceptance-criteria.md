# AI生成コード受入基準

## 基本原則

AI生成コードは、生成された時点では未レビュー成果物である。  
以下の基準を満たさない場合、採用しない。

## 受入条件

- [ ] 変更許可範囲内のみ変更している
- [ ] 変更禁止範囲に触れていない
- [ ] 仕様にない処理を追加していない
- [ ] 既存ログ形式を維持している
- [ ] 既存CSVヘッダを維持している
- [ ] 例外処理方針を維持している
- [ ] DB登録処理を変更禁止とされた場合、変更していない
- [ ] 1メソッド50行以内
- [ ] 1クラス300行以内
- [ ] ネスト3段以内
- [ ] テストケースが提示されている
- [ ] 未確認事項が明記されている
- [ ] 人間が確認すべきポイントが明記されている

## 採用不可条件

以下に該当する場合、動作しても採用しない。

- [ ] 変更範囲外を変更している
- [ ] 既存処理を勝手に整理している
- [ ] 仕様にない改善を追加している
- [ ] ログ形式を変更している
- [ ] 例外処理を変更している
- [ ] DB処理に副作用がある
- [ ] CSV項目数が不安定
- [ ] テストケースがない
- [ ] 未確認事項がない
- [ ] 「確認済み」と書いているが証跡がない

## 人間レビュー重点箇所

- DB更新
- トランザクション
- 例外処理
- CSV出力
- ログ出力
- 変更禁止範囲
- 受入条件との対応
- 未確認事項

## 採用判定

|判定|条件|
|---|---|
|採用可|受入条件を満たし、人間の確認で重大指摘なし|
|条件付き採用|軽微な指摘のみ。追加修正後に再確認|
|不採用|変更範囲外変更、仕様逸脱、未確認事項隠蔽、テスト不足|
