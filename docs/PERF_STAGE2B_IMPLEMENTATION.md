## 実装内容

| 対象 | 変更と維持した条件 |
|---|---|
| request() | 論理要求ごとに_retryContextを作り、通常GETとP経路の401後再送へ引継ぐ。一時的障害の追加最大2回と401後再送1回は別枠。D07のcatchとD08のcatch外という例外経路は変えない |
| scores/sheet_api.js | 楽譜API独自の401再送にも同じ予算オブジェクトを引継ぐ。no-store、アカウント検査、HTTPエラーを構造化結果として返す契約を維持 |
| transport_retry.js | 呼出元の予算があれば使用し、直接呼出しは呼出ごとに作成。GET以外に自動再試行を追加しない。408/429/502/504の対象と250/750msを維持し、消費済みの予算は401後も戻さない |
| 理由不明503 | 追加最大1回、500〜1,500msのジッター。一時的予算2回の内数。Retry-Afterの秒数を尊重し、日時形式/不正値は未指定相当。巨大値でタイマーがオーバーフローして即時再送されることを防ぐ |
| 既知503 | detail.codeのread_capacity_exceeded/save_busy/maintenance/version_clock_anomalyを再試行しない。既存のメンテナンスの本文とヘッダーを組合せて判定。秒数だけでメンテナンス扱いにしない。サーバーの本文/秒数は変更しない |
| 本文保護 | 分類はresponse.clone().json()で行い、HTML/空/不正JSONでも原Responseを呼出元へ返す。後段のP/F等のJSON解釈をこの変更だけで直したとは扱わない |
| 中止 | 再試行待機中のabortはタイマー/リスナーを解除し、次の送信へ進まない。明示的timeout/abortを自動再試行しない |
| 内部プロパティ | fetchWithTimeoutの既存の除去箇所へ_structuredResult/_retryContextを追加。呼出元optionsを直接書換えず、requestのローカルcopyに予算を付ける |
| 認証確認 | fetchPortalSessionCheckが同コンテキストの実行中送信と応答分類だけを共有。解析済み結果を返し、Responseを複数回読まない。完了結果はキャッシュしない |
| 認証の呼出元 | isPortalAuthenticatedの3状態・送信省略・AUTH_ENDと、tryRecoverPortalSessionの真偽値を維持。device欠落時の差を維持。apply/clearは外側に残す |
| 古い認証応答 | deviceId、認証世代、ローカル遷移カウンターを確認。clear・明示ログイン開始・logout・認証キー/deviceのstorageイベントでカウンターを進める。保存の応答epoch変化は認証を失効させない。正当な先行apply後は共有結果の期待世代を更新し、他の合流者を誤って捨てない |

認証確認は認証要求自身の予算を持つ。データの予算を消費せず、合流者が増えても認証の予算を増やさない。実行中参照のfinallyは自分が登録した参照と一致するときだけ解除する。

logoutに追加したのは古い認証応答を失効させる遷移だけ。extras/19遅延フラグを一括で消す修正やページ再読込みは実装していない。#145/#146の修正と混ぜない。
