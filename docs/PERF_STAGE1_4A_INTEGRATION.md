## 023の有無と既定値

`PORTAL_READ_CONTEXT_PATHS` と `PORTAL_VERSION_ETAG_PATHS` は未指定なら空。空のときはPortalCacheRouteからsnapshot_responseへ入らず、起動時にも版管理のschema検査は行わない。023がなくても通常の起動・HTTP読取・保存は可能であり、第3段階のコードを含めることと有効化することは別である。

一方、023なしでsnapshotのみを有効にすると起動時self-checkで停止し、版ETagも有効ならプール初期化で停止する。旧経路へ自動フォールバックする設計ではない。起動時の設定変更を迂回して要求を送った場合も、版情報不足は読取用の503で止まる。

`test_stage1_4a_schema_compatibility.py` は専用loopback PostgreSQLに限り、023の有無それぞれで既定設定のプール初期化、起動self-check、実lifespan、一覧200/304、bootstrap、#150の省略写真維持を確認する。誤有効化時の停止も確認する。024〜033はどちらにもない。

本統合版は023のSQLファイルを含む。現行の配備workflowは全SQLを適用するため、023を適用しない配備を選ぶ場合は、このSHAをそのまま配備しない。別途レビュー済みの配備対象またはmigration選択方式が必要。今回は配備判断も適用も行わない。

版ETagの有効化にはpooler容量に加え、非所有者・非保守ロールなど既存のverify_schemaによる検査がある。現在判明しているアプリの所有者ロールのまま版ETagを有効化できるとは扱わない。023適用と機能有効化を混同しない。

## 計測データ

元の生データは4Aブランチ `0060e1c` に保持する。統合ブランチはその履歴を祖先にせず、生計測の大型JSON11本を集計へ変換してから最初のコミットを作った。公開する統合履歴にも元の大型ファイルは含まれない。

同じパスのJSONは `summary_schema: 1` を持つ集計であり、従来の生レコード配列ではない。件数、条件別の最小・中央値・最大、元ファイルのSHA256・バイト数を記録する。nullや未計測を0とせず、異なる条件を混ぜない。過去の文書からリンクされた値は過去の計測であり、今回の再計測成功を表さない。

再計測の出力先は `.tmp/perf_stage*` へ移した。`scripts/summarize_perf_report.py INPUT OUTPUT --source COMMIT:PATH` で要約を再生成できる。元の写真fixtureは比較の再現性のため維持する。#150を含む現在の再実行では写真省略は維持を期待し、過去の全削除を期待する計測は履歴として区別する。

4Aまでの内容はsquashで統合したため、旧4A・4Cのコミットは統合後mainの祖先ではない。旧4Cブランチをそのままmainへマージしない。R25とロール分離の確認後に再開するときは、統合後mainから作り直して4C固有の変更だけを選択して取り込むか、旧4A `0060e1c` より後の変更を統合後mainへrebaseする。既存ブランチは比較用に保持する。

取り込み時はmainの#150と最新依存を正とし、重複する旧#150コミットを二重に加えず、album repositoryの差分更新・接続引数・省略項目保護の最終差分を確認する。024〜033は、この第1〜4Aの配備とは別にレビュー・適用判断を行う。

## 配備境界

Deploy Testはdisabled_manuallyを維持する。実DB・GCS操作、配備、migration適用は行わない。PR #147〜#149は統合PRに置き換える。既存の別作業 `docs/archive/` を保持する。

実DBでの023 preflightと4AのNOT NULL条件は既に別記録で確認済み。pooler容量・役割分離、R25、実iPhone、ASGI切断時ログと5xxの配備後確認は、このローカル・CI試験で代用しない。4C/4Dの有効化は保留する。

レビュー後の配備候補は本PRマージ後のmainとし、追加migrationは023、読取・版ETagの設定は空のままとする。実際の適用前にmigration履歴・バックアップ・書込排出を確認し、他の未適用migrationがあれば同じ許可に含めず止める。適用・検証・配備・機能有効化は別の工程であり、この記録は実行済みを意味しない。

023のトリガーは機能設定が空でも書込時に動く。実DBの読取専用preflightはschema・制約・データ整合性の検査であり、実環境での書込負荷試験ではない。隔離PGの結果だけで本番負荷を保証しない。配備前後で保存APIの応答時間・エラー/タイムアウト・save_busy件数を比較し、通常書込の5秒ロック待ちは変更しない。画像・録音（MP3変換）・health・ASGI例外/5xx・iPhone実機受入と併せて記録する。

GitHubでworkflow全体をdisabled_manuallyにしたままworkflow_dispatchを開始する運用はできない。SHAを指定した手動配備には、実行時の一時的な有効化、または自動起動と手動起動を分けるレビュー済みの方法が必要。自動配備を防ぐ具体的な手順を確定するまで無効を維持する。このマージ作業では有効化もdispatchも行わない。
