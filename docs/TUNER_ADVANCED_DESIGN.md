## 1. 対象と採用判断

全5フェーズを完成範囲とし、途中のフェーズで機能を省略して完成とはしない。対象は単音の実音測定、音源、時系列解析、練習、個人診断、楽器プロフィール、履歴である。移調・楽譜連携・団員間共有・入力和音分離・録音は対象外。改善提案は規則で生成し、AI・外部推論APIは使わない。

| 論点 | 設計で採用する内容 | 理由・変更点 |
|---|---|---|
| A4 | 390.0～480.0 Hz、0.1 Hz刻み、初期442.0。内部は整数 `a4Tenths` | 最新追加仕様T-011を満たす。現行430～450整数制限を拡張する |
| A4操作 | −／＋で0.1 Hz、数値入力、440／441／442／443のプリセット | 以前の直接入力なし方針からの変更。未確定入力は直前の有効値を維持 |
| 探索・再生範囲 | 28～4,700 Hz、標準音名C1～C8 | C1@390=28.99、C8@480=4,566.56 Hz。余裕は調整値で精度保証ではない |
| 再生と測定 | 既定は排他。同時使用は毎回の入場でイヤホン使用を宣言して有効化 | 混入判定は警告のみ。同時再生区間は診断・成長統計へ採用しない |
| 一時停止 | 「表示を固定」は収集継続。「測定を一時停止」はトラック・解析を解放 | マイクが動いている意味を明確化。再開は新しい音声区間 |
| 履歴 | 既定保存しない。手動／自動を利用者が選択。端末内に時系列、DBに要約のみ | 保存なしで測定・練習・その場の結果確認を使用可能 |
| 所有者 | 再利用しない所有者UUID＋サーバー側の団員世代確認 | 数値member_idのみで履歴を結び付けない |
| 他人の履歴 | 管理者も閲覧不可 | 所有者単位の認可。管理画面権限で迂回しない |
| 公開 | 実験室の管理者限定を維持。団員公開は別のリリース判断 | 全機能実装と一般公開を別にする |
| ビブラート幅 | 片振幅±A centと全幅2A centを併記 | 異なる定義での比較を防ぐ |
| ブラウザー | 能力検出を必須とし、最低版の保証は実機試験後 | 調査段階のSafari版候補を保証へ格上げしない |

## 2. 構成・責務・読み込み

```text
capture.worklet -- MessageChannel --> analysis.worker
    PCM取得のみ                       YIN / FFT / RMS包絡 / 品質フラグ
                                          |
                                measurement_store（生測定列）
                                 /          |             \
                          display_filter note_events   spectrogram
                              |             |
                          測定表示      analysis_stats -- trainer -- diagnosis
                                              |
                                  storage_local / storage_remote
playback + scheduler ----- 再生状態と予定時刻 ----> 上記の区間判定
```

`launcher` はポータル入退場・権限・起動世代を所有し、`controller` は入力経路、`playback` は出力経路、`session_coordinator` は両者の意図と遷移を所有する。`index.js` は配線と公開APIに絞る。新しい状態は `portalAppState` に置かない。認証参照のみ `portalRuntimeContext.appState` を使う。

Workerは重い解析と時系列統計、主スレッドは状態遷移・縮約表示・保存制御を担当する。`analysis_stats.js`等の純粋関数をWorkerとVitestで共有する。全FFTを主スレッドへ送らない。解析Workerが停止しても履歴閲覧と設定編集を利用可能にする。

ライブの`analysis.worker`はYIN・FFT・包絡計算を優先する。`measurement_store`は主スレッドで小さな数値列を有界保持し、onsetと音符の軽い状態更新を行う。区間集計・ビブラートfit・履歴診断は遅延作成する別の`stats.worker.js`へsnapshotを渡し、ライブ解析を塞がない。transferには専用コピーを使い、稼働中リングのArrayBufferをdetachしない。統計Workerは要求を最新1件へまとめ、内部タブが閉じてもライブ音声は停止しない。

既存のクラシックスクリプト、IIFE、`module.exports`、Workerの`importScripts`を維持。Workletは自己完結し、`addModule()`以外の動的importを導入しない。新ファイルも統一release IDに含める。音声のprotocolは2、保存schemaと統計規則は別の版とする。初期ページのスクリプトを増やさず、測定本体を先読みし、解析・練習・履歴UIは初回タブ表示時に順序付きで読み込む。失敗したPromiseのみ再試行可能に戻す。

起動時に本体・Worker・Workletのrelease/protocolを照合。不一致では音声を解放し再読み込みを案内する。CIで `generate:tuner-release` の生成漏れを検出する。SharedArrayBuffer、COOP/COEPの追加は不要。

## 3. 画面・操作

メインタブは「測定／音源／解析／練習／診断」。すべて `#systemTunerHost` の子に作る。履歴・楽器・設定は画面内メニューから開く。内部タブ切替では音声経路を作り直さない。ポータルのタブ・パネル・履歴による退出では従来どおり解放する。

| 画面 | 主な内容 |
|---|---|
| 測定 | 音名・Hz・cent・高低、入力レベル、信頼度案内、固定目標、音律、スペクトル |
| 音源 | 最大4声、音色、各音の指定方式、和音、ドローン、時間・繰り返し、音量 |
| 解析 | 時系列のHz／cent／dBFS、スペクトログラム、区間選択、音符イベント、各指標 |
| 練習 | 課題・条件・準備時間・テンポ・実行状態・結果・保存 |
| 診断 | 音別マップ、件数・セッション数・分布・方向・強弱・期間・比較条件 |
| 履歴 | 期間・楽器・練習種別の検索、詳細、前回比較、出力、削除 |

通常表示は音名と主偏差を優先し詳細を畳む。詳細表示で信頼度・相対音量・比較音律を開く。音名は英語／ドレミ／併記（初期）と♯優先／♭優先／音律の綴り（初期）を選択する。綴りだけの変更では周波数を変えない。ピタゴラスでは実際の綴りを必ず併記する。

主周波数は小数1桁Hz、主偏差は整数centを基本表示し、詳細では小数1桁centを併記する。目標・純正比からのコピー・分析計算はこの表示丸めを使用しない。

基準Hz変更は確定した値だけを即反映。範囲端の±はdisabled。メーターは±10／25／50（初期）／100 cent、許容幅は3（初期）／5／10／任意0.5～25、0.5刻み。合格帯のCSS幅は `2*tolerance/(2*meterRange)` で計算し表示端で切る。判定は許容幅で入り、許容幅+1 cent超で解除。目標変更では旧合格状態を解除する。

応答速度は表示設定の組とし、高速=平滑40 ms／新音1回確認／無効後500 ms保持、標準（初期）=120 ms／2回／1,000 ms、安定重視=240 ms／3回／1,500 msを初期調整値とする。新音確認は同じ候補音が許容30 cent以内で連続した回数。音名変更・30 cent以上の跳躍は平滑状態をリセットする。平滑時間は0～500 ms、10 ms刻みで個別変更可能とし、変更後は「カスタム」と表示する。解析窓・保存生値・ビブラート計算をこの設定で変えない。

「表示を固定」「測定を一時停止」は別ボタン。マイク動作、表示固定、解析停止、再生、同時使用は文字とアイコンで明示する。権限再要求は必要時だけ案内。全画面APIが使えない場合は画面内最大化へ切り替え、終了ボタンとポータルへ戻る導線を保持する。

操作領域44 CSS px以上。390 pxだけでなく277／320／390／430 pxで横幅を検証。ダークモードはOS追従／明／暗、高コントラストを別設定とする。グラフは色だけで区別せず線種・単位・数値表を併用する。音名読み上げは安定800 ms、最短2秒間隔を初期値とし、更新値を常時live regionに流さない。区間選択は2本のハンドルと開始・終了の数値入力でも可能。最大2倍音の誤り等を断定的な演奏批評にしない。

<a id="lifecycle"></a>
## 4. ライフサイクルと競合制御

単一の肥大化した状態enumではなく、`visibility / captureState / outputState / displayFrozen / practiceState / persistenceState`を直交して管理する。禁止組合せはcoordinatorで拒否する。`captureState=running`と`outputState=playing`は同時使用を明示したときだけ許可する。

| 操作・状態 | 入力 | 出力 | 記録・評価 |
|---|---|---|---|
| 入場・再開 | 起動し自動測定 | 停止 | 新区間。許可待ちはstartingに統合 |
| 内部タブ・設定閲覧 | 継続 | 現状維持 | 継続。非表示のCanvasだけ停止 |
| 表示固定 | 継続 | 現状維持 | 生値収集継続。固定表示は別スナップショット |
| 測定一時停止 | トラック・Worker解放 | 独立した再生は継続可 | 解析区間を閉じる。課題もpaused |
| 排他再生 | 停止・旧値消去 | 再生 | 再生区間は演奏評価から除外 |
| 排他再生の停止 | タップ内でContext準備、停止完了+250 ms後に取得 | フェード停止 | 新区間。残響待ち時間は実機調整 |
| 同時再生 | 継続 | 再生 | 表示とその場の参考値のみ。保存系列には除外フラグ |
| 退出・背景・ログアウト | 即時解放 | 即時停止・予約取消 | 区間を閉じ、実行中課題はpaused／interrupted |
| 復帰 | 現在の画面・認証を確認して再開試行 | 自動再生しない | 新しい音声区間。練習再開は利用者操作 |

通常の再生・停止ではフェードを用い、退出・権限喪失では待機せず停止する。`getUserMedia`前後、各await、遅延コールバック、結果受信、保存完了のすべてで世代と所有者を照合する。

維持する識別子: `navigationTicket`、`activationGeneration`、`captureEpoch`、`playbackGeneration`、`ownerEpoch`、`axisId`、`saveGeneration`。役割を混同しない。再生開始では予約済み測定再開と準備Contextを取り消す。遅れて到着したマイク・Wake Lockはその場で解放する。古い測定の完了が新しい再生を止めないよう、リソースは取得した世代だけを破棄する。

タップ内ではawaitより先にContextを作りresume。launcher未着なら既存実験室の準備処理を使う。背景移行ではその準備分も閉じる。ページ復帰と許可UIからの復帰を区別し、再開不可時だけ「タップして測定を再開」を表示する。

分析結果ごとの可視・認証guardと500 ms監視を維持し、再生中・起動中・保存中にも適切なguardを置く。Wake Lockは入力か出力が可視状態で稼働中だけ要求し、要求世代を照合。取得拒否は機能失敗にしない。ユーザーの音量・OSルーティングを自動変更しない。

<a id="capture"></a>
## 5. 入力・解析・実効時刻

マイクはmono優先、echoCancellation/noiseSuppression/autoGainControl=falseを要求し、取得後の確認値を条件に記録する。対応しない制約を無効化済みとは扱わない。入力は `source → capture Worklet → Gain(0) → destination`、Worklet出力もゼロ。処理ブロック長は実配列から得る。[Workletの仕様上の注意](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletProcessor/process)

sampleRateは実取得値を使用し、探索・発音・表示をNyquist未満に制限する。低sampleRateで全設計音域を扱えない場合は利用可能範囲を表示し、未対応の目標は選択不可にする。標準sampleRateへの強制変更だけで端末の入力条件が揃ったと扱わない。

チャンクは1,024サンプル、プール8個を設計初期値とする（48 kHzで約46.9転送/秒）。入力欠落・プール不足は部分チャンクを捨て、gapを送る。WorkerでもsequenceとstartFrameの連続性を検証する。catch-up解析を積まず最新区間を評価する。欠落時間を測定時間へ埋め合わせない。

### 5.1 音域とYIN

FFT相関＋累積二乗和によるYINを維持し、スペクトルは候補の品質確認に利用する。スペクトル最大ピークで基音を置き換えない。

| プロファイル | 探索と窓 | 出力の初期設定 |
|---|---|---|
| 全音域（初期） | 28～4,700 Hz、長窓。短窓への適応切替を検証して導入 | pitch 30 Hz、RMS包絡100 Hz |
| 低音重視 | 28～880 Hz、長窓 | pitch 20 Hz、RMS包絡100 Hz |
| 高音重視 | 110～4,700 Hz、短窓。範囲外は案内 | pitch 40 Hz、RMS包絡100 Hz |
| ビブラート詳細 | 110～4,700 Hz、短窓 | pitch 40 Hz。低音の幅は未評価なら数値を保留 |

`tauMax=ceil(sampleRate/minHz)`、`W=ceil(1.5*tauMax)`、`N=W+tauMax+1`。48 kHzでは長窓N=4,288（約89.3 ms）、短窓N=1,094（約22.8 ms）。精度と信頼度を犠牲にして短窓を全低音へ使用しない。表示30 fpsと解析頻度は独立し、rateを上げても1,024チャンクの到着頻度が上限になる。

適応切替の調整値: 長窓で3回連続140 Hz以上を確認したら短窓へ、短窓で2回連続120 Hz未満または100 ms信頼度不足なら長窓へ戻す。短窓中も長窓を5 Hzで監視し、低音への跳躍で倍音を追い続けない。切替後は最低2フレームを比較確認し、窓版・modeを記録。切替時の非単調な実効時刻は後述の並べ替えで扱う。切替試験に未合格なら自動切替を公開せず、長窓と手動プロファイルを維持する（最終受入の未完項目として残す）。

無音閾値は手動−90～−20 dBFS、初期−60。自動では利用者の静音校正2秒のRMS中央値＋12 dBを同範囲へclampし、演奏中の音を使って閾値を追い上げない。信頼度0.8は現行の周期性尺度であり確率ではない。アタック・音量急変・ゼロ連続・クリッピング・範囲外を別reason/flagで保持し、棄却値を0 Hzや0 centの観測として使わない。

基音欠落の識別不能条件や整数倍成分だけの音は、候補間の曖昧さを記録して統計を保留する。無理に特定音名へ補正しない。50 Hzハム等を音高検出器だけで楽器と区別できるとはしない。練習目標との不一致は「環境音の可能性」であり、演奏ミスと断定しない。

### 5.2 時刻・通知

`startFrame`は包含、`endFrame`は非包含。`centerFrame=(startFrame+endFrame-1)/2`（サンプル添字の平均）を基本の実効時刻とし、窓依存の偏りは合成FMで検証する。半フレームは保存前に丸めず、保存契約の2倍フレーム番号に変換する。音声のepochが変われば基準フレームとサンプルレートを新しく記録する。

`AudioContext.currentTime`、`performance.now()`、UTCを同じ時刻と扱わない。epoch開始時と定期的に対応点を記録する。取得できれば `getOutputTimestamp()` は出力スケジュールとの対応に使うが、マイクのハードウェア入力遅延を校正した証拠にはしない。[出力時刻API](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)

画面向けpitchは得られ次第、スペクトル10 Hz、解析用短窓FFT20 Hz、RMS包絡100 Hz。解析通知は最大50 msごとにまとめても、pitch描画を250～500 ms待たせない。スペクトルは対数512点へ縮約する。

イベント処理は最大150 msの時刻並べ替えバッファーを持ち、窓の違う結果と包絡をcenterFrame順に確定する。watermarkより古い遅延結果は集計を二重更新せず、lateフラグで残す。セッション終了では未確定分をflushし、欠落境界をまたいで並べ替えない。ライブ表示は最新入力を描き、確定統計の遅延とは分ける。

<a id="temperament"></a>
## 6. 共通目標モデル・音律

`target_model.resolve(config, detectedHz?)`は `{targetHz, equalHz, midi, spelling, role, ratio, temperamentVersion}` を返す純粋関数。Hzの直接値、音名、音律連動を区別する。自動音名は平均律で候補を選んでも、課題の正確性評価の目標に流用しない。

| 音律 | 定義 |
|---|---|
| 平均律 | `f(n)=A4*2^((n−69)/12)`。自動はヒステリシス付き最近傍、固定は指定n |
| 純正短3度・長3度 | 平均律の根音Hz×6/5、×5/4。既存モードを互換維持 |
| 長／短三和音 | 平均律根音×{1,5/4,3/2}または{1,6/5,3/2}、役割を明示。指定音域へ2^k移動 |
| 7度を含む和音 | 既定の長7=15/8、短7=9/5。短7は16/9・7/4も明示選択可。プリセットに比を保存 |
| ピタゴラス | 基準音の平均律Hzをanchorに、kが−3～8の12個の五度 `(3/2)^k` をoctave正規化。基準Cの既定綴りはE♭からG♯。切れ目はk範囲の開始位置として保存 |
| カスタム | anchor音を平均律Hzに固定し、12音の偏差−100～+100 centを0.1刻みで指定。anchor偏差は0。比入力は正の比からcentへ変換して同じ範囲を検証 |

ピタゴラスは基準がCならG♯とE♭の間が切れ目。調変更時は綴り付き五度列を移調し、選択した切れ目を表示する。A4設定はanchorの平均律Hzを決める値で、他音律のA4自体が必ずその値になるとは限らない旨を詳細表示する。anchorをA4にすればA4実音も設定Hzに固定される。単なる♭優先表示で別の比に切り替えない。

対象音域外のrole・octaveは選択不可。平均律との差は同じ目標midiの `equalHz` と比較する。設定の確定時はrawHzを変えず条件区間を閉じる。境界をまたぐ音符イベントは左右に分割し、分割直後を人工的なアタックとして評価しない。音律・A4・根音・役割・許容幅変更ではinTuneを解除して再計算する。

<a id="sound"></a>
## 7. 音源・スケジューラー

最大4voice。各voiceは `fixedHz / note / linkedRole`、音域28～4,700 Hz。Hz入力0.1刻みだが、比から計算・コピーした値は丸めない。fixedHzは設定変更へ追従せず、noteはA4へ、linkedRoleはA4・音律・根音・roleへ追従。「再生欄に設定」はfixedHzのスナップショットとし、勝手に発音しない。

音色はサイン／三角／倍音合成（最大40成分）。カスタム倍音は各音のNyquist未満だけを構成し、係数と正規化方式をpresetに保持する。ブラウザー標準波形でも高音を実波形で検証する。波形ピークを正規化し、masterGain上限0.25、初期40%→0.1、各voice gain=1/activeVoiceCountを基本とする。音数変更もrampし、4音の同位相最悪入力でclipしないことを検証する。DynamicsCompressorNodeだけで真のピーク上限を保証しない。

発音20 ms、停止30 ms、周波数glide30 ms、音量20 msを初期値とする。再予約時は `cancelAndHoldAtTime` 対応時は利用し、非対応では自前の包絡状態から時刻tの値を求めて繋ぐ。`AudioParam.value`が予約中の瞬時値と一致すると決めつけない。

プリセットは長三和音、短三和音、属7、長7、短7、半減7、減7。平均律の半音列はそれぞれ[0,4,7]、[0,3,7]、[0,4,7,10]、[0,4,7,11]、[0,3,7,10]、[0,3,6,10]、[0,3,6,9]。純正比を定義していない和音は平均律であると明示し、カスタム比で拡張する。和音再生は入力和音分離を意味しない。

持続／指定時間0.1～600秒／繰り返し（1～100回または停止まで）、交互／同時再生。テンポ30～240 BPM、先読み100 ms、タイマー25 msを調整値にする。発音・停止時刻はAudioContextの時刻へ予約し、JSタイマーは補充だけに使う。停止では予約済み全voice・click・後続繰り返しを世代で無効化する。背景では補充し続けず停止し、自動再生しない。

同時モードでの再生予定は、入力epochの対応時刻・同期誤差付きで `playbackInterval` として送る。異なるContext間の変換を毎回対応点から求める。再生区間に前後250 msと推定同期誤差の余白を加え、診断統計から除外する。メトロノームもスピーカー出力であれば同じ規則。イヤホン宣言は端末判別ではない。条件を満たさず診断可能時間が不足した場合は結果を保留する。

<a id="analyzer"></a>
## 8. 時系列・音符イベント・音響解析

### 8.1 表示とバッファー

時系列のライブ表示は30秒、10／30／120秒を選択し、解析用数値は直近30分をリングで保持。保存を有効にしたセッションは別の逐次書き込み領域へ流し、リングの上書きで保存データを失わない。保存なしで30分を超えた場合は古い詳細系列が失われることを表示し、イベント集計は最大2時間・10,000イベントまで保持する。上限でセッションを分割し、測定は継続する。

Canvasは最大30 fps。非表示タブは描画しない。時間軸を画素ごとのmin/maxへ縮約してピークを保持し、欠落区間は線で結ばない。cent／Hz／dBFSは同一epochの実効時刻へ揃える。グラフの固定は表示スナップショットであり、記録を停止しない。

時間軸はピンチ／拡大縮小ボタンと横スクロールで操作し、10秒～保存済みセッション全体を表示できる。縦軸はcent／Hz／dBFSの表示切替と個別範囲指定を持つ。追従表示へ戻るボタンで最新時刻に戻す。選択区間は絶対時刻で保持し、ズームで対象が変わらない。

スペクトルは既存の500～16k／25～16kを維持。スペクトログラムは512行相当・10 Hz・u8表示強度で直近5分、約1.536 MBを上限とする。解析用dBFSからの量子化は表示専用。全FFTはWorker内で直近分だけ保持。選択区間がリング外なら詳細の再現不可を表示する。

### 8.2 発音と定常区間

RMS包絡は10 ms窓・10 ms hop。onsetは校正ノイズ床+12 dBかつ直前50 ms中央値より6 dB上昇を候補とし、20 ms継続で確定。offsetは閾値以下30 ms継続。すべて調整値。音程イベントは音量候補と、前後の有効Hzの持続的な変化を併用する。同音反復は音量の谷と再アタックで分け、ビブラートの上下を別音符へ分けない。

同音判定は目標ではなく観測midiと±50 centの継続性を用いるが、目標への正確性計算は独立。指定目標から遠い値も勝手に正解へ吸着させない。イベントのstart/endはonset包絡時刻。pitch有効値の初出時刻を真の発音時刻と呼ばない。

定常区間候補はonset+100 ms以降、連続200 msでピッチ中央値の移動±5 cent以内・音量傾き10 dB/s以内。ビブラート課題では中心線で判定する。初期閾値は合成音・実楽器で調整する。アタックは発音後0～100 msの有効観測、リリースはoffset前200 msの有効観測と定常との差。観測がない区間は「測定できず」とし、最初の100 msを後の安定値で埋めない。

クリッピングは±1近傍の連続値に加え、上下の平坦部も候補にし、検出不能な端末前段歪みは限界として残す。clip区間の音程を使える場合も、倍音評価は除外する。

### 8.3 指標

区間のcentは保存された目標Hzから `1200*log2(rawHz/targetHz)`。平均（A-014）、中央値、標準偏差、min/max、p10/p90を別々に保持する。中央値への置き換えで「平均音程」の要件を消さない。重みは観測の支配時間で、変則hopのフレーム数を時間とみなさない。

観測iの支配区間を隣接center時刻の中点で区切り、イベント境界でclipする。隣接間隔が予定hopの2倍を超えるところ・欠落・棄却・汚染はunknownとして切り、gapを補間しない。定常時間・安定時間は有効な支配区間の長さの和で求める。

`validMaintenance = inToleranceSeconds / validEligibleSeconds` と `coverage = validEligibleSeconds / requestedPerformanceSeconds` を必ず併記。無音・棄却・gap・再生汚染は分母に混ぜて0 centにせず、理由別秒数を表示する。低coverageで高維持率だけを成功表示しない。練習時間は準備・再生・休止を除く実演奏指定時間も別に記録する。

ドリフトは実効時刻に対するcentの重み付き直線回帰。再現性は試行ごとのイベント代表値の標準偏差。アタック安定時間は、以後300 msにわたり200 ms窓の中心が許容内にある最初の時点を候補にする。十分な先行観測がない場合は「最初の有効観測まで」を下限として表示し、真の安定時刻と断定しない。

### 8.4 ビブラート・倍音

短窓の未平滑化centに、不規則時刻をそのまま使う重み付き正弦＋直線トレンドを3～10 Hzで当てはめる。基準は最低2秒・5周期・有効coverage80%以上（調整値）。候補周波数0.05 Hz刻みを細分化し、残差・非周期モデルとの改善・周期別CVを併記する。条件不足や候補が一意でなければ保留。速度、±片振幅、全幅、中心、周期別速度／幅CVを返す。10 Hz解析は40 Hzの実測系列が得られる条件だけを対象とし、低rateの系列でNyquist付近を強引に数値化しない。

倍音は基音近傍帯域を含むHann窓補正済み電力を用いる。相対強度は `harmonicDb − fundamentalDb`、基音が検出限界以下なら相対値を未定義にする。最大40倍音、Nyquist・帯域重なり・clipの有効性を各成分に付ける。発音部は4,096点、定常部は16,384点を使い、窓長・時刻を明記して比較する。低音の発音部で分解能不足なら値を出さない。強弱比較は同楽器・同音・同取得条件内に限り、音色の良し悪しを採点しない。

倍音ごとの時間変化はライブの直近5分で表示する。履歴比較用にはイベント単位で発音部・定常部の最大40成分の平均電力、基音、相対値、有効数、窓、区間を数値要約として保存する。全FFTとスペクトログラム画像は保存しない。過去履歴ではこの要約とpitch系列を再表示し、保存していないスペクトログラムの再現を装わない。倍音要約の容量は18 B/frameのpitch系列試算とは別に計上する。

## 9. 練習トレーナー

課題は `{exerciseVersion, targetEvents[], tempo, prepSeconds, tolerance, targetConfig}` にコンパイルする。targetEventは目標音・音律・予定時刻・長さ・休符・強弱指示・表示可否を持つ。準備3秒、音長2秒、60 BPMを初期値とし、楽器音域を超える課題は開始不可。

| 練習 | 生成規則・評価 |
|---|---|
| ロングトーン | 指定音・長さ。アタック、定常、ドリフト、維持率、coverage |
| 半音階 | 半音で指定範囲を上行／下行／往復。折返し重複の有無を明示 |
| 長音階 | 12調、[0,2,4,5,7,9,11,12] |
| 短音階 | 自然[0,2,3,5,7,8,10,12]、和声[0,2,3,5,7,8,11,12]、旋律は上行[0,2,3,5,7,9,11,12]・下行自然短音階 |
| 跳躍 | 2度～2オクターブ。方向・音程種別と同音域の目標を指定 |
| 同音反復 | 音量包絡で再アタックを数え、発音とpitchの再現性を分離 |
| 強弱変化 | 音量の相対的傾向とpitch中心の変化。校正音圧を要求しない |
| 音感 | 参照を再生→停止→残響待ち→表示を隠して演奏→結果表示 |
| インターバル聴音 | 2音を再生し利用者が音程を回答。録音評価と別の正解率 |
| カスタム | 最大256音、テンポ・時間・休符を指定。構文検証後に実行 |
| メトロノーム | schedulerで予約。音が出る区間は混入除外し、光の拍も選択可 |
| ウォームアップ | 音域・音長を段階化した課題列。自動で音を鳴らして開始しない |

状態は `idle → configuring → countdown → performing → result → saving`、performingからpaused/interrupted/cancelledへ遷移する。countdown中は統計対象外。課題中の条件変更・背景移行はpauseして区間を閉じ、復帰後は利用者が再開する。途中終了は部分結果であり完遂と数えない。

観測イベントと期待列の対応は時刻制約付き動的計画法で行う。挿入・欠落・誤音のコストを分け、実際の音高差を残す。近い音へ丸めて正解化しない。開始ずれ許容はmax(100 ms,拍の25%)を調整値とし、測定窓の遅延を差し引くのではなく実効時刻で合わせる。無音の課題イベントにも未演奏結果を作る。

結果は正確性・安定性・発音安定性・維持率・再現性・改善度を個別表示。総合スコアは初期無効。選択時は版付き重みを示し、必須指標不足なら合計しない。ロングトーンは正確性0.4/安定性0.3/維持率0.3、ビブラートは中心0.4/周期再現性0.3/幅再現性0.3を暫定重みとする。正規化基準が実機で未評価なら総合スコアの公開を保留し、全機能完成の未完項目として管理する。

## 10. 個人診断・楽器・比較

音別マップはmidi（実音・octaveあり）で集計し、平均・中央値・分布・件数・セッション数・期間・conditionsKeyを表示。色は高低の方向を示すだけで、文字の符号と数値を併記。タップでイベント、時系列、条件、除外理由を確認する。

長音や長い1セッションが過大に効かないよう、1)イベント内時間重み付き平均・中央値、2)同条件同音のセッション代表値、3)セッションを同じ重みで集約、の階層を設ける。I-001の平均値を必ず出し、堅牢な傾向値として中央値も併記。ばらつきはイベント内とイベント間・セッション間を区別する。

推定区間はセッションをclusterとして再標本化し、フレームを独立標本としてbootstrapしない。診断の開始条件は有効5イベント・3セッション以上、各イベント150 ms・3有効観測以上・coverage80%以上を調整値とする。さらに95%推定区間が広すぎる場合は「参考値／データ不足」。この下限は統計的保証ではなく、実機・模擬集計で調整する。

conditionsKeyはA4・音律版と全目標定義・楽器とsetting版・課題版・方向・強弱指示・engine版・統計版・取得条件の校正IDを正規化したhash。各比較は異なる項目を明示し、変更対象以外を揃える。端末や距離が変われば新校正ID。同一端末でも自動マイク処理や部屋が変わる場合を利用者に記録させる。

強弱は利用者のp/mf/f等の指定とセッション内相対RMSで分類し、別端末のdBFSを音圧として比較しない。上行・下行・跳躍は直前の課題／有効イベントとのintervalで分類。同じ音の反復は独立カテゴリ。

高低傾向は推定区間が0を跨ぐ場合は断定しない。弱点順位は十分なデータのある音だけについて中央値絶対値・セッション間ばらつきを別順位で表示。改善度は同条件の直近群と過去群の差と不確実性を示し、利用回数だけで上達としない。規則例: 「E5の偏差が高め→E5のロングトーン」「上行だけ不安定→上行音階」。理由と件数を併記し、楽器故障や奏法原因を推測しない。

楽器プロフィールは名前・種類・メーカー・型番・任意名、リード等のsetting版、調整日・メモ、低中高の音域境界を持つ。種類から境界の候補を設定するが利用者が変更可能。設定変更前後の履歴は別条件として保持する。削除では通常アーカイブし、履歴削除は別操作。気温−10～50℃、湿度0～100%、warmup未記入／済／時間を任意記録し、原因推定には使わない。

## 11. 保存・履歴・個人データ

保存先と保存頻度は独立設定。頻度はnone（初期）／manual／auto、保存先はlocal（初期）／local+account。音律・音源presetとUI設定の「端末に保存」は、演奏履歴の保存とは別の明示操作とする。現行A4だけは互換で自動保存し、他設定の永続化は設定保存を選んだ場合のみ行う。

noneではディスクへ系列・結果・プロフィールを保存しない。manualは結果画面で保存。autoは練習開始時または自由測定の「セッションを記録」で始め、測定画面を開いただけで長期履歴を作らない。1秒単位の一時保存は選択済みセッションのみ。端末容量不足では自動削除せず保存停止を明示し、音程測定は継続する。

詳細系列は標準Float32形式（量子化形式は初期不採用）、時刻・reason・flagsを含める。端末内は90日または100 MB、セッション2時間・10,000イベントを設計初期上限とする。期限前に書き出しと削除を案内し、利用者が選択した保持規則だけを実行する。生PCMはディスク・ログへ書かない。

アカウントへは明示opt-in時にセッション・イベント・結果・楽器・preset要約を送信。詳細系列とスペクトログラムは送らず、別端末での詳細グラフは「この端末に詳細データなし」と表示する。DBだけで詳細グラフを復元できると約束しない。CSVはイベントと統計、JSONはschema付き数値系列も含めたローカル出力を選べる。

保存操作の所有者は開始時に固定。ログアウト・所有者変更時に未送信要求を中断し、古い所有者のデータを新しい所有者で再送しない。共有端末の残存・削除・アカウント世代の詳細は別紙契約に従う。プライベートブラウズやサイトデータ消去による損失を説明し、永続化APIの許可を保証としない。[WebKitの保存方針](https://webkit.org/blog/14403/updates-to-storage-policy/)

## 13. 検証・性能予算・受入

調査のPC合成音結果と30分主スレッド測定は、スマートフォンの精度・消費電力の保証ではない。以下は実装時の設計目標とし、未達は測定条件付きで報告する。既存テストの期待を下げて通さない。

| 分類 | 受入条件・測定方法 |
|---|---|
| 数式 | A4=390/430/440/442/450/480、C1～C8、各音律・role・異名同音・固定Hz。既知比との相対誤差1e−9以下（保存Float32は別許容） |
| 定常音 | 純音・倍音音・弱い基音・基音欠落・位相・SNR別。主要域SNR30 dBで有効値のp95誤差±2 cent目標。有効率、棄却、全入力に対する粗大誤り、オクターブ誤りを別報告 |
| 曖昧な入力 | 基音を識別できない音は数値精度達成としない。判定保留率と誤った有効率を測り、識別可能音と分ける |
| 過渡・時刻 | 跳躍・FM・glissando・短い同音反復・強弱で真値のイベント時刻と比較。境界±50 ms、短反復6回の取りこぼし0を目標。低音の物理的窓制約は別表示 |
| ビブラート | 既知3～10 Hz・±10/30/50 cent、40 Hz観測、不規則hop・欠測。速度±0.1 Hz、幅±10%を目標。音域別に未達・保留を報告 |
| 音源 | OfflineAudioContextで最大4声・音色・同位相・変更中もabs peak<1、指定周波数、フェード、予定時刻誤差1ブロック以内を確認 |
| 状態競合 | 遅延launcher、許可待ち退出、背景、履歴連打、再生停止250 ms内の再生、古いtimer・Worker・Wake Lock・save完了を実際の結合で再現 |
| 統計 | 同じ音を長くしても試行n不変、セッション内イベント数で重みを増やさない、欠測・同時再生は0 cent化しない。条件・engine版を跨ぐ比較を拒否 |
| 保存・認可 | 改ざんowner・別tenant・別会員・ID再利用・旧session・ログアウト後の再送・削除後の遅延送信を拒否。offline、容量不足、migration失敗でも測定可能 |
| UI | 277～430 px、キーボード・VoiceOver・ダーク・高コントラスト。音名とHzの単位、読み上げ頻度、範囲切替時の古いaxis破棄 |
| CPU・遅延 | 代表端末でWorker p95解析1回<10 ms、音声由来の実効時刻から画面反映p95<200 ms（標準）、メイン描画p95<8 msを目標。音域・窓の遅延を併記 |
| 長時間 | iPhone/Android/PCで30分以上。意図しない中断0、チャンク欠落率<0.1%、メモリーが上限内で収束。Worker/Workletを含む測定と、mainのみの測定を区別 |
| 電池・発熱 | 輝度・音量・端末・OS・充電・電池状態を固定し、現行版と30分A/B。新機能有効時と測定のみを別測定。持続的スロットリングで追従目標未達なら公開保留 |

実マイク・実楽器はクラリネット、ヴァイオリン、低音（コントラバス等）、高音（ピッコロ等）を含み、音域、距離、部屋、奏法、別の基準測定を記録。検証音の収録は別の同意・保存・削除方針を定めてから行い、共有ZIPへ入れない。

ブラウザーは候補のSafari/iOS17以降、Android Chrome現行と直前主要版、PC Chrome/Edge/Firefox/Safariの現行・直前主要版を試験表にする。PWA・通常タブ・イヤホン・スピーカーを分ける。能力検出でWake Lock・fullscreen・永続化が使えなければ代替で動かすが、未試験OSを動作保証とはしない。

## 14. フェーズ・移行・公開

| Phase | 完了内容 | 前提・公開条件 |
|---|---|---|
| 1 | 入出力状態共通化、protocol2、実効時刻、YIN窓、A4拡張、感度・固定音・許容幅・表記・全音律・presetローカル保存 | 保存設定を履歴から分離して先行実装。iPhone初回・停止・窓切替を先に試験 |
| 2 | 音源拡張・scheduler、時系列・spectrogram、イベント・ロングトーン・基本ビブラート | Phase1の契約を使用。同時再生は統計除外。結果はメモリー内で閲覧可能 |
| 3 | 全練習メニュー・対応付け・結果・比較指標 | 期待列と観測の音響的検証を通す。永続履歴へ依存せず練習可能 |
| 4 | 保存・楽器・履歴・DB要約同期・所有者・診断・提案・出力削除 | DB/API契約と本人分離・ID再利用試験。Phase2の保存ボタンを本接続 |
| 5 | 実楽器・端末別最適化・詳細倍音・長期比較・ビブラート精度・全体回帰 | 未達の数値・機能を未完一覧から消さず、201要件をすべて受入判定 |

旧A4キー `portalTunerReferenceA4Hz` は整数430～450のみ読んで×10し新設定へ移行。不正なら4420。旧キーを読める互換を移行期間に残し、新設定を旧キーへ小数で逆書きしない。新しい設定はschema版を検証し、未知の版を破壊的に初期化しない。履歴・音源・音律presetは版付きmigrationをtransactionで適用し、失敗時は読み取りとエクスポートを残す。

初期公開は引き続きシステム管理者だけ。団員公開・本番昇格・実音声収録・履歴の自動送信は、この設計作成によって実行されたことにしない。機能フラグを戻せば旧測定UIへ戻れるよう移行し、データschemaは前方互換を保つ。ロールバックで履歴を削除しない。
