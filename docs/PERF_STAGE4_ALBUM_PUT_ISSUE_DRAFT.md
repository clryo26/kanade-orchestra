# Issue #150: アルバム汎用PUTで写真を省略すると写真行が全削除される

状態: 2026-10-23、ユーザーの本文送信承認を受け [Issue #150](https://github.com/clryo26/kanade-orchestra/issues/150) として起票済み。以下は送信した本文。既存リンクのためファイル名は維持する。性能改善とは別の不具合として扱い、起票で修正済みとはしない。

## 問題

汎用 `PUT /api/extra/albums/{id}` に名前だけを送り `photos` を省略すると、200で成功する一方、そのアルバムの写真メタデータ行がすべて除去される。省略を「変更なし」とするか、置換APIとして扱うかの契約を別仕様で確定し、性能改善とは別の変更として修正・レビューする。

## 確認済みの証拠と未確認の範囲

- コミット `ed94b1f` の `tests/backend/test_perf_stage4_postgres.py` の省略payload試験で、隔離PostgreSQL 16/18の架空データ各25写真について再現した。応答は200・写真空、DBの対象写真行は0となり、監査1件が確定する。
- `db_item_repository.py::_write_children` は子集合を全DELETEした後に再INSERTする。写真を省略して空集合に正規化される経路ではINSERTされない。
- 現行のこの試験ではGCSオブジェクトを削除していない。実DB・実GCSのデータ損失を確認したものではない。
- `src/static/js/modules/albums.js` に汎用PUTによる名前編集の明示呼出しは見当たらない。動的なURL指定、他の呼出元、外部API利用・保守での使用は未確認。画面からのデータ損失が発生したと断定しない。
- 計測報告: `docs/PERF_STAGE4_0_POSTGRES_BASELINE.md` 7章。固定写真付きの名前変更試験とは分離している。

## 第4段階への影響と停止条件

現在はGCS原画像が残っていればメタデータ修復の余地があるが、4C/4Dの回収機構を有効にすると、誤って除去された参照が回収候補となり、7日後の物理削除に至るおそれがある。

- 4Cの差分更新実装へ着手する前に、本Issueの別仕様で写真省略の意味と呼出元への影響を確定し、修正と回帰試験をレビューする。
- 本Issueの修正・検証が完了するまで、4Dの物理回収を有効にしない。
- 4Aの読取最適化や4-0の読取専用調査の前提にはしない。
