# メトロノーム機能 全要件追跡表

確認日: 2026-10-18。入力は利用者提示の「メトロノーム機能 統合仕様案 Ver.1.0」全文と事前調査依頼。**全機能を採用する。フェーズ01a・01b・02〜05は実装順序であり優先順位ではない。** 本表の実現性は実装完了を表さず、調査に基づく【推定】、振る舞い/検証は【設計目標】である。確認した既存事実・一次資料・計測は[実現性調査](METRONOME_FEASIBILITY.md)、作業・試験・未確定事項は[実装計画](METRONOME_IMPLEMENTATION_PLAN.md)を参照する。

| 記号 | 定義 |
|---|---|
| 01a | 基盤契約と方式比較。音楽時間、tempo map、transport/fence、共通出力 |
| 01b | 基本/拍子/設定UI、初回tap/退出/背景/logout停止と初期実機 |
| 02 | 高度なリズム。混合、poly、連符、swing、拍子sequence |
| 03 | 練習トレーナー。tempo変化、mute、裏拍、拍感、記録 |
| 04 | オーケストラ。休符、cue、指揮、楽曲map、fermata、modulation |
| 05 | 演奏解析/チューナー連携/端末精度の最終受入。実機の初期確認は01bから実施 |
| 提案 | 仕様の一覧にはあるが開発フェーズ欄で個別に指定のない項目に対する配置案 |
| 純 | 純粋関数、偽時計、モデル/境界/数値/validator試験 |
| 波 | OfflineAudioContext等のレンダリング波形・sample位置・peak検証 |
| 結 | ブラウザー結合。DOM、Worker/Worklet、AudioContext、IDB/API等 |
| 実 | 版を記録した実機。物理出力/マイク/タッチ/割込み/電池等 |
| — | 独立要件、または依存なし。依存は主要な技術依存で全ての推移依存を列挙しない |

実現性は「そのまま可」「制限付き」「実機確認が必要」「代替が必要」のいずれか。前者も既存コードの無改修流用という意味ではなくWebで表現可能という判断である。iOSの振動などは機能全体を不採用にせず端末別の代替を要求する。末列の未検証は今回の未試験を指し、実機が必要なものは「実機」と明示する。
